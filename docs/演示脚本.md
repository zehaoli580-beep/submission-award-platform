# 业务闭环现场演示脚本（逐步照做版）

> 前提：MySQL（黑窗口开着）、后端 8080、前端 5173 都在运行，浏览器打开 http://localhost:5173
> 每换角色前：先点右上角【退出】再登录下一个账号
> 全程约 8-10 分钟，练习时建议开着这份脚本对照走
> **演示视频统一用：`桌面\大作业素材\演示视频-H264.mp4`（已验证可在线播放；手机/录屏导出的 mp4 多为 H.265 编码，浏览器会黑屏有声，不要用）**

## 演示账号一览

| 角色 | 账号 | 密码 |
|---|---|---|
| 作者 | author | author123 |
| 管理员 | admin | admin123 |
| 审稿人1 | reviewer | review123 |
| 审稿人2 | reviewer2 | review123 |

> 注意：库里已有演示数据（2 篇已录用稿、2 个已公示奖项）。演示新链路会新增一篇稿、一个新奖项，不会冲突。

---

## 第一幕：作者投稿（约 1.5 分钟）

**账号：author / author123**

1. 登录页输入账号密码，点【登 录】
2. 进入作者工作台，讲一句："顶部是稿件概览条，我的每篇稿按状态一目了然"
3. 左侧【提交新作品】表单：
   - 作品标题：`校园四季航拍`（演示时可自拟）
   - 作品分类：选 `短视频`
   - 作品简介：随便写一句，如 `记录校园春夏秋冬的航拍剪辑`
   - 作品文件：选一个 mp4 文件（**提前在自己电脑放一个几MB的测试视频**）
4. 点【提 交 作 品】→ 提示"投稿成功, 等待编辑部初审"
5. 右侧【我的稿件】出现新纪录，状态是灰色的【待初审】
6. **亮点展示**：表格"作品"列有一个【播放】按钮，点它 → 弹窗在线播放视频 →
   说："数字媒体作品不用下载就能直接在线预览"

## 第二幕：管理员初审 + 分配（约 1.5 分钟）

**账号：admin / admin123**（先退出 author）

1. 登录后进入管理后台，先指顶部：**"6 张统计卡片——待初审现在是 1"**
2. 第一个 Tab【待初审稿件】能看到刚投的《校园四季航拍》
3. 点该行的【通过并分配】→ 弹窗里多选勾选 **评审老师(reviewer)** 和 **评审老师二号(reviewer2)**
   - 说："初审通过和分配审稿人是一个事务，一步完成"
4. 点【通过并分配】→ 提示成功
5. 切到【外审与终审】Tab，稿子出现在这里，状态【外审中】
   - 演示**追加审稿人**按钮存在但不用点（省时间）

## 第三幕：审稿人盲审（约 2 分钟）

**账号：reviewer / review123**（先退出 admin）

1. 登录进入审稿工作台，【我的评审任务】里出现《校园四季航拍》
   - **关键讲解点**："看，这里只有标题、分类、简介、文件——**看不到作者是谁**，这就是盲审，后端返回的数据里抹掉了作者信息"
2. 点【提交意见】抽屉：
   - 评分：`88`
   - 推荐结论：选【推荐录用】
   - 评审意见：写一句，如 `画面稳定，剪辑节奏舒适，色彩统一`
3. 点【提 交 评 审 意 见】→ 成功
4. **可以演示防重复**：再点一次提交意见 → 会被拒绝，说："一人一票，重复提交被后端拦截"

**账号：reviewer2 / review123**（退出，换审稿人2）

5. 同样步骤给这篇稿提交意见：评分 `75`、推荐录用、意见随便写
6. 提交成功 → 两位审稿人意见齐了

## 第四幕：管理员终审（约 1.5 分钟）

**账号：admin / admin123**

1. 【外审与终审】Tab → 点《校园四季航拍》的【查看意见】→ 抽屉展示两位审稿人的打分和意见
   - 说："终审前能看全部意见"
2. **先演示防线**：这里如果意见没齐点终审会被拒（刚才已凑齐，口述即可）：
   "后端强制：审稿人没交齐意见，终审接口直接拒绝，前端绕不过去"
3. 点【终审】→ 选【录用】→【确认决议】→ 提示"终审决议已生效"
4. 顶部统计卡片【已录用】数字 +1

## 第五幕：评奖（约 2.5 分钟）

**账号：admin / admin123**（继续用）

1. 切到【奖项管理】Tab → 点【+ 创建奖项批次】：
   - 名称：`2026秋季优秀数字媒体作品评选`
   - 说明：随便写
2. 创建成功后列表出现【筹备中】→ 点【开启评审】→ 确认 → 变【评审中】
3. 点【提名作品】→ 下拉框里只有"已录用"的稿 → 选《校园四季航拍》→【提名】
   - 说："只有已录用的作品才有资格进评奖池"

**账号：reviewer / review123**（退出换审稿人1）

4. 切到【奖项评分(评委)】Tab → 下拉选刚才的奖项
5. 给《校园四季航拍》打 `92` 分，点【保存】
6. 讲解："打分公示前可以反复改，保存即覆盖"

**账号：reviewer2 / review123**（退出换审稿人2）

7. 同样打 `80` 分，保存

**账号：admin / admin123**（退出换回管理员）

8. 【奖项管理】→ 点该奖项的【公示定奖】→ 获奖名额保持 `1` →【公示并定奖】
9. 讲解算分规则："只有 2 位评委时直接取平均 = (92+80)/2 = **86**；评委满 3 人以上会自动去掉最高分和最低分再取平均，防止一票操纵结果"

## 第六幕：公示页收尾（约 1 分钟）

**账号：任意，建议 author / author123**

1. 顶栏点【获奖公示】
2. 刚才的奖项已展开：**领奖台大卡片**（🥇 金色渐变、作品名、作者、终评分 86、进度条）
3. 说："所有角色登录后都能看到这个公示页，这是平台公正性的出口"
4. **最后一击**：回到作者工作台 → 点这篇稿的【流转记录】→ 时间线展示：
   "从投稿、初审、分配、外审、录用到评奖，每一次状态变更都有留痕——谁、什么时间、从什么状态改成什么状态。整个平台的状态流转全部走后端状态机，作者端没有任何改状态的接口，非法流转直接抛异常。"
5. 收尾一句："以上就是这个平台从投稿到评奖的完整业务闭环，谢谢老师。"

## 演示前检查清单

- [ ] 提前准备好一个测试视频文件（mp4，几 MB 即可）放桌面
- [ ] 三件套全部运行（MySQL 黑窗 / 后端 / 前端 npm run dev）
- [ ] 浏览器开 http://localhost:5173 能正常显示登录页
- [ ] 全链路自己先彩排一遍（第一次约 15 分钟，熟练后 8 分钟）
- [ ] 每次切换角色记得点右上角【退出】

## 常见意外与救场

| 意外 | 救场话术/操作 |
|---|---|
| 登录报"系统繁忙" | MySQL 黑窗口被关了 → 重新双击 start-mysql.bat 再登录 |
| 5173 打不开 | 前端终端被关了 → 重新 npm run dev |
| 演示中断网/卡死 | 重启对应服务，库里的旧演示数据（2 篇已公示奖项）随时可顶上 |
| 视频弹窗播放不了 | 视频编码是 H.265（手机/录屏常见），浏览器解不了 → 换用 `桌面\大作业素材\演示视频-H264.mp4` 重新投稿演示 |
